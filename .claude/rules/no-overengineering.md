# No Overengineering

- Simple solution first — justify complexity before introducing it
- Don't add features, abstractions, or error handling beyond what the task requires
- Three similar lines is better than a premature abstraction
- No half-finished implementations
- Don't design for hypothetical future requirements

## Comments
- Comment only complex code, and keep it brief
- Don't comment why a decision was made or why something changed — that belongs in the commit message
- No comments that restate what the code does
