# Project Structure

Single Nuxt 4 app (not a monorepo). Full plan: `.docs/plan.md`; task breakdown: `.docs/tasks.md`.

```
scorpio-logs/
├── app/            # components/ (base, fight, roster, layout), composables/, pages/, layouts/
│   └── workers/    # Web Workers (log indexing + parsing run off the main thread)
├── server/         # Nitro server routes
│   ├── api/        # fights/, groups/, rosters/, icons/, esologs/
│   └── utils/      # supabase.ts, esologs.ts
├── shared/         # pure TS used by app, server and workers (no Vue/Nitro APIs)
│   ├── parser/     # Encounter.log tokenizer, line streaming, indexer, session → FightModel
│   ├── types/      # FightModel and other domain types (auto-imported)
│   └── utils/      # coverage math (interval union, uptime, merged effects) (auto-imported)
├── types/          # database.ts (generated — never edit)
├── scripts/        # one-off Node scripts (e.g. build sets.json from LibSets)
├── .docs/          # product thinking: plan.md, tasks.md, estimates/YYYY-MM-DD-slug.md
│   └── sample-logs/ # full-fight Encounter.log extracts (one valid log per fight) — see its README
├── specs/          # features/*.md — written BEFORE code
├── tests/          # unit/, integration/, e2e/, fixtures/ (small Encounter.log slices)
├── supabase/       # migrations/ (timestamped SQL), seed.sql
└── public/
```

## Rules
- Build `app/components/base/` (Button, Card, Badge, ...) before feature components
- `types/database.ts` is generated by the Supabase CLI — regenerate, don't hand-edit
- Every feature has a spec in `specs/features/` before implementation
- Two doc homes, no others: `.docs/` holds product thinking (plan, tasks, estimation reports) plus the reference sample logs in `.docs/sample-logs/`; `specs/features/` holds one spec per feature — acceptance criteria, decisions, test plan. Estimates never go in a spec; specs link to them
- Schema changes go in a new timestamped migration in `supabase/migrations/` — never edit an applied migration
- `shared/parser/` must stay free of DOM, Node and Vue APIs so it runs in a Worker and on the server alike
- Never commit a full `Encounter.log`. Full-fight samples live in `.docs/sample-logs/` (each file < 50 MB, source recorded in its README); tiny hand-cut slices for unit tests live in `tests/fixtures/`
